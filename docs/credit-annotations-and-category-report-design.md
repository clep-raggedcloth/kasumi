# クレジット明細の補足・カテゴリと月次カテゴリ構成の設計

## 目的と範囲

クレジット明細の「Amazon」などの支払先だけでは購入内容が分からないため、明細ごとに利用者が補足を記録する。クレジットにもカテゴリを設定し、クレジット・現金払い・固定費を合わせた月次のカテゴリ別支出額と割合を表示する。以前カテゴリを手動で選んだ支払先には、次の明細でそのカテゴリを初期設定する。

対象は既存の月次レポート画面、PDF、CSVアップロード、SQLiteのデータモデル。CSVの元データと既存の合計方法は維持する。

## 現状と変更方針

| 現状 | 変更方針 |
| --- | --- |
| `Transaction.memo` はCSVの備考 | 別列 `user_note` を追加し、利用者の「補足」を編集可能にする。CSV備考はデータとして保持するが画面・PDFには表示しない |
| `Transaction.category` は存在するが入力・表示・集計されていない | 明細ごとに編集・表示する。`NULL` は「未分類」として扱う |
| 現金払いと固定費ではカテゴリの選択肢が異なる | 共通のカテゴリ定義を1か所に置き、新規入力に使う。既存データの文字列はそのまま表示・集計する |
| 月次レポートはクレジットの除外を合計とPDFに反映する | カテゴリ集計にも同じ除外条件を適用する |

## 画面と操作

1. 月次レポートのクレジット明細の行内にカテゴリのプルダウンと補足の1行テキストボックスを常時表示する。支払先、日付、金額は読み取り専用で同じ行に残す。カテゴリ未設定は「未分類」と表示する。
2. 変更した行にだけ「保存」「元に戻す」を表示する。保存時にその行のカテゴリと補足を一緒に送信する。保存中・保存済み・失敗を行内に表示し、失敗時は入力内容を残して再試行できるようにする。JavaScriptが使えない場合も行内の保存ボタンから通常のフォーム送信で保存できる。ポップアップの編集画面は使わない。
3. 同じ支払先のカテゴリを以前手動で選んでいれば、新規アップロードしたクレジット明細にはそれを初期設定する。明細画面で個別に変更できる。特にAmazonは買い物ごとに分類を変えられる。
4. サマリーの下に「カテゴリ別の支出」を置き、円グラフ、凡例、金額、割合を表示する。色だけで区別せず、カテゴリ名と数値を併記する。支出が0円ならグラフの代わりに空状態を表示する。
5. PDFにもクレジットのカテゴリ・補足と同じカテゴリ構成を載せる。PDF用の円グラフはサーバーでSVGを生成し、ブラウザと同じ集計結果を使う。

補足は表に収まる1行テキストボックスとし、500文字まで入力できる。列見出しは「補足」のみとし、CSV備考は表示しない。PDFには保存済みの補足を全文表示する。行内のカテゴリ・補足にはアクセシブルな名前を付け、キーボード操作で保存・取消ができるようにする。

## データモデル

```text
transactions
  id, statement_id, date, merchant, amount, memo, category, excluded, ...
  user_note TEXT NULL              # 新規。利用者が入力する補足

merchant_category_defaults        # 新規
  merchant_key TEXT PRIMARY KEY    # 正規化したCSVの支払先
  category TEXT NOT NULL           # 次回取り込み時の初期カテゴリ
  updated_at TEXT NOT NULL         # 最終手動選択日時（UTC）
```

- `Transaction.memo` はCSV備考として保持し、編集APIから変更しない。`user_note` は空文字を `NULL` に正規化し、最大500文字に制限する。
- カテゴリの共通選択肢は「食費、日用品、交通、医療、娯楽、住居、光熱費、通信、保険、教育、サブスク、その他」。クレジットのみ「未分類」も選べるが、保存値は文字列の「未分類」ではなく `NULL` に統一する。新規入力はこの集合でサーバー側でも検証する。既存の自由入力カテゴリが集合外でも削除・変換せず、選択欄に現在値を出し、その明細・支払いを変更せず再保存する場合は現在値を許可する。
- `merchant_key` は支払先を Unicode NFKC 正規化し、前後の空白除去、連続空白の1文字化、英字の大文字化で作る。同じCSV支払先の表記ゆれを限定的に吸収し、曖昧な部分一致や「Amazon」を含む文字列すべての同一視はしない。元の `merchant` は変更しない。
- 編集時にカテゴリが実際に変わったときだけ、その `merchant_key` の既定値を upsert する。「未分類」に変えた場合は既定値を削除する。補足だけの編集、CSV取り込み、除外切り替えでは既定値を更新しない。
- 既定値の変更は**将来取り込む明細のみ**に適用する。過去明細や、同じアップロード内の別明細を一括変更しない。明細またはCSVファイルを削除しても既定値は維持する。

### 既定カテゴリが確定する時点

先月のレポートからカテゴリを集計して決める方式ではない。ある支払先の明細でカテゴリを変更して「保存」した時点で、そのカテゴリがその支払先の次回用既定値になる。同じ支払先で複数の明細を編集した場合は、最後に保存した変更が優先される。CSVアップロード時点の既定値を新しい明細にコピーするため、その後に既定値を変えても取り込み済み明細は変わらない。古い月の明細を編集して保存した場合も、現行仕様では次回用既定値を更新する。クレジット明細の見出し付近に「カテゴリ変更は次回の同じ支払先の初期値にも反映」と説明を表示する。

## 保存・取り込みの流れ

1. 既存の `POST /transactions/{id}/edit` で行内フォームの `category` と `user_note` を受ける。取引IDを確認し、カテゴリと補足を検証する。明細の変更と支払先既定値の更新を1トランザクションで保存する。通常送信はレポートへ303で戻し、非同期送信は成功・エラーをJSONで返す。
2. `GET /transactions/{id}/edit` は既存リンクとの互換用に残す。月次レポートではこのページやダイアログへ移動せず、行内で直接編集する。
3. CSVアップロード時は各 `merchant` から `merchant_key` を作り、既定値があれば `Transaction.category` にコピーする。なければ `NULL`。取引に割り当てた後のカテゴリは既定値とは独立している。
4. 既存の `transactions` には `user_note` 列だけを追加する。`category = NULL` はそのまま「未分類」。既存のCSV備考を利用者補足へ移さない。新規テーブルは `CREATE TABLE IF NOT EXISTS` 相当のマイグレーションを用意する。`create_all` だけでは既存テーブルへ列が追加されないため、起動時の移行処理も更新する。

## 月次集計と円グラフ

集計対象月は既存レポートの基準に合わせる。クレジットは明細の `Statement.year/month`、現金払いは支払日、固定費はその時点で有効な登録分を毎月計上する。クレジットの `excluded=True` は集計から外す。

| 値 | 定義 |
| --- | --- |
| カテゴリ別支出額 | 対象の各明細・現金払い・固定費のうち、`amount > 0` の金額をカテゴリ別に合計。クレジットの `NULL` は「未分類」 |
| 円グラフの分母 | 全カテゴリの支出額の合計。割合は `カテゴリ別支出額 / 分母 × 100` |
| 返金・調整 | 対象のクレジット・現金払い・固定費すべてについて、`amount < 0` の金額を符号付きで合計して別表示。円グラフには入れない |
| 月次総合計 | 従来どおりクレジット、現金、固定費の符号付き金額を合計する |

円グラフは「支出構成（返金・調整を除く）」と明記する。たとえばクレジットの3,000円の購入と固定費の -1,000円の調整があれば、グラフの支出額は3,000円、月次総合計は2,000円となる。`円グラフの分母 + 返金・調整 = 月次総合計` を満たす。金額0円の項目はいずれにも加算しない。カテゴリ別の金額・割合は同じ分母から計算し、表示割合の丸めによって合計が100.0%とずれる場合は表示上の丸めと分かるようにする。グラフのデータ順は支出額の降順、同額ならカテゴリ名順で固定する。

## 実装箇所

| 箇所 | 主な変更 |
| --- | --- |
| `app/models/database.py` | `user_note`、支払先既定値テーブル、移行処理 |
| `app/routers/upload.py` | 支払先既定値を参照して新規明細のカテゴリを設定 |
| `app/routers/reports.py` | 明細編集APIの非同期送信用JSON応答、既存の通常送信への303応答を維持 |
| `app/templates/report.html` | クレジット明細の行内プルダウン・テキスト欄・保存状態。ダイアログを削除し、保存後はレポート全体を再取得して合計とグラフを同じ状態で表示 |
| `app/templates/_transaction_edit_fields.html` | 互換用の編集ページに残す。行内フォームと同じ選択肢・500文字制限を使う |
| `app/templates/pdf_report.html` | カテゴリ・補足・構成の表示 |
| `app/routers/cash_expenses.py`, `app/routers/expenses.py`, `app/templates/fixed_expenses.html` | カテゴリ選択肢を共通化し、登録APIでも検証 |

円グラフは外部のチャートライブラリを増やさずSVGで作る。サーバー側でカテゴリと角度を計算すれば、JavaScriptを使わないPDFにも同じデータを渡せる。行内の保存後はレポート全体を再読み込みし、カテゴリ金額・割合・凡例・総合計を同じサーバー計算結果に揃える。再読み込み時は保存対象以外の補足・カテゴリの編集中の値を復元し、現金払いの保存や除外切り替えでも同様に保持する。保存に失敗したときは再読み込みせず、入力値とエラーを行内に残す。保存中の同じ行の二重送信を防ぐ。

実装順は、(1) 各行のカテゴリ選択欄と補足欄を既存値で描画し、行の操作欄にフォームを置く、(2) 表の別セルに置く入力欄を `form` 属性でそのフォームへ紐付ける、(3) JavaScriptでは変更がある行だけ保存・取消を表示し、送信結果を行内へ表示する、(4) 非同期保存成功時にレポートを再読み込みする、の順。JavaScriptなしでは保存ボタンを常時表示する。表の行を `<form>` で直接囲まず、有効なHTML構造を保つ。

## 受け入れ条件

- Amazonの2件に異なる補足とカテゴリを保存でき、再表示・PDFでもそれぞれ維持される。CSV備考は変更されない。
- Amazonで「日用品」を手動保存した後に取り込んだAmazon明細は「日用品」で始まり、別カテゴリへの変更もできる。既存のAmazon明細は変わらない。
- 支払先の表記ゆれは定義した正規化範囲で一致し、異なる支払先には既定値が伝播しない。「未分類」を選ぶと次回の初期カテゴリも解除される。
- クレジット・現金・固定費の正額のカテゴリ別支出額の合計が円グラフの分母と一致する。除外した明細は含まず、どの支払い方法の負額も返金・調整に集計する。`円グラフの分母 + 返金・調整 = 月次総合計` が成り立つ。
- 補足とカテゴリの編集、現金払いの追加・編集・削除、クレジットの除外切り替え後に画面の割合と金額が更新される。ブラウザ表示とPDFの数値が一致する。
- 行内でカテゴリ・補足を変更して保存・取消できる。補足だけの保存は支払先既定値を変えず、カテゴリの保存はその場で既定値を更新する。保存失敗時には入力値が残る。
- 既存DBを移行してもCSV備考、明細カテゴリ、除外状態は保持され、未分類の明細もレポートに残る。
